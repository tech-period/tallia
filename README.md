# Tallia

ゲームのタイトルごとに、ゲーム内オブジェクト（アイテム、素材、モンスターなど）の
所持数・配置状況を記録するための個人用メモツールです。

- 認証なし・サーバーなしの静的サイト。外部への通信は一切行いません
- データはすべて利用者のブラウザ内（IndexedDB）に保存されます
- PWA としてインストールでき、完全オフラインで全機能が動作します

詳細な仕様は [docs/design.md](docs/design.md) を参照してください。

## データモデル

```
Project（ゲームタイトル）
  ├─ ProjectImage（イメージ画像。1 プロジェクトにつき 1 枚）
  ├─ Category（オブジェクトの分類。1 オブジェクトにつき 1 つ）
  ├─ Tag（オブジェクトに付けるしるし。1 オブジェクトに複数）
  ├─ Master（そのタイトルに登場するオブジェクトの定義）
  │     ├─ MasterImage（イメージ画像。1 オブジェクトにつき 1 枚）
  │     ├─ categoryId → Category
  │     └─ tagIds[]   → Tag
  └─ Case（記録の単位：ダンジョン、章、周回など）
        └─ Instance（そのケースに何がいくつあるか）
```

Instance は数量型です。同一ケース内の同一マスターは 1 レコードに集約され、`qty` で数を持ちます。

カテゴリとタグもマスタです。オブジェクトは名前ではなく ID で参照するため、
名前を変えても参照は保たれます。オブジェクトの作成・編集ではドロップダウン
（タグはチェックボックス）でマスタから選びます。

## 画面構成

```
プロジェクト一覧
  └─ プロジェクトメニュー（カード全体をタップして入る）
       ├─ レコードリスト      … 全ケースを開いた状態で記録が並び、その場で個数を編集できる
       ├─ ケースマスタ        … ケースの追加・並べ替え・削除
       ├─ オブジェクトマスタ  … オブジェクトの追加・編集・削除
       ├─ カテゴリマスタ      … カテゴリの追加・並べ替え・削除
       └─ タグマスタ          … タグの追加・並べ替え・削除
```

- プロジェクト一覧と各マスタ画面の編集・削除はアイコンボタンです。指で押せるよう 44px 角を確保しています
- プロジェクトカードは全面がメニューへのリンクで、アイコンボタンはその手前に重ねています
- ケースの展開ビューは初期表示で全ケースを開き、それぞれの中身を `by-case` インデックスで読み込みます（見出しを押すと畳めます）
- 個数は 0 も正しい値です。0 のときはマイナスボタンが非活性になり、レコードは残ります
  （消えるのは明示的に削除したときだけ）
- ケースマスタやオブジェクトマスタの「使用中のケース」からは `?open=<caseId>` でレコードリストへ移動します（初期表示は全て展開されているため、該当ケースも開いた状態です）
- カテゴリマスタとタグマスタは同じ画面コンポーネントで、ルートの `data.kind` で切り替えています
- 使用中のカテゴリ・タグは削除できません（オブジェクトの削除と同じ方針）。使用中のオブジェクトはその場で確認できます

## イメージ画像

プロジェクトとオブジェクトに、それぞれイメージ画像を 1 枚ずつ設定できます（各作成・編集ダイアログから）。
オブジェクトの画像は、オブジェクトマスタとレコードリストにサムネイルとして並びます。

- Web の画像検索などで画像をコピーし、そのまま **Ctrl + V（Mac は ⌘ + V）** で貼り付けられます。ドラッグ&ドロップとファイル選択にも対応しています
- 取り込んだ画像は最長辺 960px に縮小し、WebP（未対応環境では JPEG / PNG）へ再圧縮してから保存します
- 画像は `projectImages` / `masterImages` ストアに `ArrayBuffer` として保存します。一覧表示で毎回読み込まずに済むよう、本体とは別ストアに分けています
- オブジェクトの画像は `by-project` インデックスで表示中のプロジェクト分だけを読み込みます
- 画像そのものではなく URL だけがコピーされている場合は取り込みません（外部への通信を行わない方針のため）

## アーキテクチャ

```
Component（表示・入力のみ）
    ↓
Service（業務ロジック、整合性ルール、状態管理）
    ↓
Repository（IndexedDB の CRUD のみ）
    ↓
IndexedDB
```

- Component から Repository は直接呼びません
- Repository は業務ルールを持たず、Angular API も `@Injectable()` 以外は使いません
- カスケード削除やインポートのトランザクション境界は Service 層が持ちます

主なディレクトリ:

| パス                         | 役割                                                          |
| ---------------------------- | ------------------------------------------------------------- |
| `src/app/core/db/`           | 型定義（`schema.ts`）と `openDB` / `upgrade`（`database.ts`） |
| `src/app/core/repositories/` | 各ストアの永続化                                              |
| `src/app/core/services/`     | 整合性ルール、状態管理、バックアップ、更新検知                |
| `src/app/features/`          | 画面（遅延ロード）                                            |
| `src/app/shared/`            | 共通コンポーネントとユーティリティ                            |

## 開発

```bash
npm install
npm start        # http://localhost:4200/
npm test         # vitest + fake-indexeddb
npm run build    # 本番ビルド
```

Service Worker は本番ビルドでのみ有効です。オフライン動作を確認する場合は
`npm run build:pages` の出力を静的サーバーで配信してください。

### アイコン

ファビコンと PWA アイコンは `scripts/generate-icons.mjs` が生成します（依存パッケージなし）。
形状や配色を変えたいときはスクリプト冒頭の定義を編集して `npm run icons` を実行してください。
`public/icon.svg` `public/favicon.ico` `public/apple-touch-icon.png` `public/icons/*.png`
がまとめて更新されます。手で編集しても次の生成で上書きされます。

## デプロイ

`main` への push で `.github/workflows/deploy.yml` が GitHub Pages へデプロイします。

- ビルドは `ng build --base-href /tallia/`（プロジェクトサイトのサブパス配信に合わせる）
- ルーティングは `HashLocationStrategy`。404.html の用意は不要です
- 出力ディレクトリ直下に `.nojekyll` を置き、`_` 始まりのファイルが無視されるのを防ぎます

リポジトリ側で **Settings → Pages → Source** を「GitHub Actions」に設定してください。

## バックアップ

設定画面から JSON のエクスポート / インポートができます。

| モード | 挙動                                                                 |
| ------ | -------------------------------------------------------------------- |
| 追加   | すべての ID を新規採番し直し、別プロジェクトとして追加します         |
| 置換   | 既存の全データを削除してからファイルの内容を投入します（二段階確認） |

ファイル形式は `format: "tallia-backup"` と `version` を持ち、読み込み時に必ず検証されます。
現行の形式は `version: 4` です。旧形式もそのまま読み込めます
（`1`: 画像なし / `2`: プロジェクトの画像のみ / `3`: カテゴリ・タグが文字列）。
`3` 以前のファイルは、取り込み時に文字列のカテゴリ・タグをマスタのレコードへ振り替えます
（同じ名前はプロジェクトごとに 1 件へまとまります）。既存の IndexedDB も
DB バージョン 4 への更新時に同じ振り替えを行います。

## マスタの移し替え

設定画面から、マスタ 4 種（ケース / カテゴリ / タグ / オブジェクト）を
`.tallia` ファイルに書き出し、別のプロジェクトへ取り込めます。バックアップとは別の形式です。

|          | バックアップ                 | 移し替え                             |
| -------- | ---------------------------- | ------------------------------------ |
| 目的     | 同じデータをそのまま復元する | 別のプロジェクトへマスタの定義を配る |
| 対象     | 全ストア                     | マスタ 4 種とオブジェクトの画像      |
| Instance | 含む                         | 含まない                             |
| ID       | ファイルに含む               | 含まない（名前で突き合わせる）       |
| 拡張子   | `.json`                      | `.tallia`                            |

突合キーは各マスタの名前です。同じ名前のものがあったときの扱いは、そのままにする /
ファイルの内容で上書きする（メモ・イメージ画像・カテゴリとタグの割り当て）の 2 つから選べます。
**どちらでも既存のマスタが削除されることはありません。**

オブジェクトとカテゴリ・タグの紐付けも、ID ではなく名前で運びます。取り込み時に
取り込み先の同名のカテゴリ・タグ（無ければ新しく作ったもの）の ID へ結び直すため、
移し替え先でも紐付いた状態になります。ファイル形式は現行が `version: 2` で、
紐付けを持たない `version: 1` のファイルも読み込めます（その場合は未設定で取り込まれます）。

`.tallia` の実体は JSON ですが、手で開いて編集するファイルではないため独自の拡張子にしています。
誤って別のファイルを取り込まないための検証は拡張子ではなく、`format: "tallia-masters"` と
`version` の確認で行います。
